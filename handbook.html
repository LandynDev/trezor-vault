trezor-vault handbook

How to run a proxied 2-of-3 vault on Bittensor with a Trezor and btcli 11.3.0.

Names

NameMeaning
vault-NPure proxy that holds the funds. Its only delegate is multisig-N (Any, delay 0).
multisig-N2-of-3 multisig: the btcli signer, the Trezor signer, the backup signer.
Trezor signerPure proxy that the Trezor controls. It is one of the 3 signers.
<btcli wallet>btcli wallet of the btcli signer.
btcli deviceComputer with btcli and the btcli wallet.
Trezor deviceComputer with this repo, a browser, MetaMask, and the Trezor.

One person opens a call on the btcli device. The Trezor approves it. The call then runs as vault-N.

This handbook assumes that the Trezor signer, multisig-N and vault-N exist. To create them, see README.md (create-signer, sign --create-vault).

1. One-time setup

Trezor device

  1. Clone the repo: git clone <repo url> ~/trezor-vault && cd ~/trezor-vault
  2. Check the commit: git rev-parse HEAD must equal the published commit hash.
  3. Install: npm ci --ignore-scripts. Never run npm install or npm update.
  4. Create the config file ~/.trezor-vault/vaults.json:
{
  "N": {
    "net": "main",
    "trezor": "<0x address of the Trezor>",
    "signer": "<Trezor signer address>",
    "signers": ["<btcli signer address>", "<Trezor signer address>", "<backup signer address>"],
    "threshold": 2,
    "vault": "<vault-N address>"
  }
}
  1. Add the alias to ~/.bashrc or ~/.zshrc, then open a new terminal:
alias vault='node ~/trezor-vault/vault.mjs'
  1. Check the config against the chain:
vault config-check --vault N

The 3 check lines must start with OK. Stop if a check line starts with FAIL. One FAIL is expected: during a delegate rotation (section 3), between steps 3 and 5, the vault has 2 Any delegates.

FieldMeaning
netmain or test
trezorEVM address of the Trezor account in MetaMask
signerThe Trezor signer (pure proxy)
signersAll 3 signer addresses. All devices must use the same 3.
thresholdApprovals needed. Default 2.
vaultvault-N

btcli device

  1. Save the multisig:
btcli multisig add multisig-N --threshold 2 --signatories <btcli wallet>,<Trezor signer address>,<backup signer address>

The printed multisig_address must equal the multisig line of vault config-check.

  1. Save the vault. <h> and <e> are the height and extIndex that were printed when the vault was created:
btcli proxy book add --name vault-N --address <vault-N address> --spawner multisig-N --proxy-type Any --delay 0 --index 0 --height <h> --ext-index <e>

2. Core loop

Every action uses the same 3 steps.

StepDeviceDo
1. Openbtcli deviceRun the btcli command from the recipe table. Note the printed multisig call hash.
2. ApproveTrezor deviceRun vault approve --vault N. Read the summary. Open the printed URL. Sign on the Trezor.
3. CheckTrezor deviceThe output must show MultisigExecuted with "result":"Ok" and no Error. Then run vault info --vault N.

Every btcli command that opens a call ends with the same flags:

-w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney

What to check before you sign

The Trezor does not show the call. The terminal summary is the only check.

LineMust be
call hashEqual to the multisig call hash that btcli printed
callproxy.proxy(real=… (vault), …), then the action you expect
AmountsThe amount you expect. Amounts show in TAO or alpha, and in rao.
AddressesCorrect in every character. A known address has a label: (vault), (multisig), (signer N), (your Trezor signer).
WARNINGRead every one. An address with no label always gives a WARNING. Stop if you do not expect a warning.
actionEXECUTE for the second approval of a 2-of-3

If more than one call is open, vault approve --vault N lists them. Run it again with the hash:

vault approve --vault N --hash <0x call hash>

3. Recipes

Step 1 commands for the btcli device. Then do steps 2 and 3 of the core loop.

GoalCommand
Pay TAObtcli wallet transfer --dest <address> --amount <tao> -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
Check balance, stake, open callsvault info --vault N (Trezor device, no signing)
List open calls on the btcli devicebtcli multisig pending -w multisig-N -n finney
Stake addbtcli stake add --hotkey <hotkey address> --netuid <netuid> --amount <tao> -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
Stake removebtcli stake remove --hotkey <hotkey address> --netuid <netuid> --amount <alpha> -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
Stake movebtcli stake move --origin-hotkey <hotkey address> --dest-hotkey <hotkey address> --origin-netuid <netuid> --dest-netuid <netuid> --amount <alpha> -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
Transfer stake to another coldkeybtcli stake transfer --dest <coldkey address> --hotkey <hotkey address> --origin-netuid <netuid> --dest-netuid <netuid> --amount <alpha> -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
Cancel an open callSee "Cancel an open call"
Rotate a vault delegateSee "Rotate a vault delegate"

Full example, pay 1.5 TAO:

btcli wallet transfer --dest <address> --amount 1.5 -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
vault approve --vault N
vault info --vault N

Amounts: <tao> is in TAO. <alpha> is in the alpha of the origin subnet.

Price limits of stake calls

CallPrice limit
Stake addYes (5% by default)
Stake removeYes (5% by default)
Stake move to another subnetYes (5% by default)
Stake move in the same subnetNo. No swap occurs.
Transfer stake in the same subnetNo. No swap occurs.
Transfer stake to another subnetNo. The swap runs at any price.

btcli sets the limit when it opens the call. Approve soon after the call is opened. If the price moves past the limit, the call fails with SlippageTooHigh. The tool reports the failure and nothing moves. Open the call again.

A stake transfer to another subnet has no price protection. To be safe, keep --origin-netuid and --dest-netuid equal.

Cancel an open call

Only the signer that opened the call can cancel it. Get the hash and the opened at <height>-<index> values from vault info --vault N. The btcli wallet signs this command directly:

btcli call Multisig.cancel_as_multi --args '{"threshold":2,"other_signatories":["<signer address A>","<signer address B>"],"timepoint":{"height":<height>,"index":<index>},"call_hash":"<0x call hash>"}' -w <btcli wallet> -n finney

other_signatories are the 2 signers that are not the btcli wallet. If btcli reports SignatoriesOutOfOrder, swap the 2 addresses and run the command again.

Rotate a vault delegate

Always add the new delegate first. Remove the old delegate second.

  1. Open: btcli proxy add --delegate <new delegate address> --proxy-type Any --delay 0 -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
  2. Approve: vault approve --vault N. A WARNING for proxy.addProxy is correct here.
  3. Check: vault info --vault N shows both delegates.
  4. Open: btcli proxy remove --delegate <old delegate address> --proxy-type Any --delay 0 -w multisig-N --signatory <btcli wallet> --proxy-for vault-N --no-mev-shield -n finney
  5. Approve and check again. vault config-check --vault N shows FAIL between steps 3 and 5. It must show 3 OK lines after step 5.

Every Any delegate can move all funds of the vault. The tool refuses to remove the last Any, delay 0 delegate, because the funds would be lost. If the new delegate is a new multisig, the old multisig must do step 4 before you update vaults.json and the btcli books.

4. Troubleshooting

MessageCauseFix
no pending callsNo call is open, or it was already executedRun vault info --vault N
more than one pending callMany calls are openRun again with --hash <0x call hash>
the call data of … was not found on chainPossible causes: the MEV shield, an open with a hash only, or a call that a Trezor signer openedPass --call <0xhex> (btcli prints multisig call data). Or cancel the call and open it again with btcli and --no-mev-shield.
--call has hash …; the pending call is …The call hex is not the open callUse the multisig call data that btcli printed
… already approved …The Trezor signer approved this call beforeAnother signer must approve
approved, NOT executedThe threshold is not reachedAnother signer must approve
inner call FAILED: …SlippageTooHighThe price moved past the limit of a stake callNothing moved. Open the call again and approve sooner.
inner call FAILED: proxy.ProxyExecuted …The call ran and failed (for example, not enough balance)Nothing moved. Read the error name, fix the cause, open the call again.
inner call FAILED: utility.BatchInterrupted … or utility.ItemFailed …One item of a batch failedOther items of the batch DID run. Run vault info --vault N and check what moved.
refusing: cannot tell which account runs …A proxy call is inside a wrapper that changes the accountCancel the call. Open it as proxy.proxy directly, or inside a batch.
… is not an Any, delay 0 delegate of …The multisig does not control that accountCheck signers, threshold and vault in vaults.json
… must have exactly one proxyThe Trezor signer has a wrong delegate setStop. Do not sign. Check the Trezor signer on an explorer.
refusing: … is the last Any, delay 0 delegateThe call would lock the vault foreverCancel the call
conflicts with vault "N"A flag is different from vaults.jsonRemove the flag, or correct the config
cannot read vault config / no vault "N"The config file or the name is missingCreate ~/.trezor-vault/vaults.json (section 1)
config-check FAILEDThe chain does not match the configStop. Compare each printed address with your records.
